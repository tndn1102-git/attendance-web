# 락다운시티 힌트폰 GM 뷰어

동시에 돌아가는 힌트폰(`fantastrick.co.kr/hint-phone/`) **2대**와 상태를 공유하며,
진행을 실시간 모니터링하고 원격 조작하는 GM용 뷰어. Cloudflare Worker로 서빙.

## 왜 Worker인가
- Cloudflare는 HTTPS → 브라우저가 `ws://`(비암호 8080)에 직접 못 붙음(mixed-content 차단).
- Worker가 **wss(브라우저) ↔ ws(8080)** 브릿지 + 정적 페이지 서빙을 겸함.

## 구조
```
[GM 브라우저] --wss--> [Cloudflare Worker] --ws:8080--> [iptime 릴레이] <--master--> [힌트폰 x2]
     뷰어 UI            /(HTML) /live(브릿지)          (simPin 패치)        (v141 패치)
```

## 개발/배포

## 2026-08-03 수정: "플레이 중간중간 미션/디테일 칸이 비어 있다" (v140)

폰의 미션·디테일이 **단계가 겹칠 때** 공백이 되거나 옛 미션으로 되돌아갔다.
원인은 표시가 "상태를 그리는" 게 아니라 **`setTimeout` 체인으로 애니메이션을 예약**해두고 **그 예약을 취소하지 않은** 것.
안전가옥 ①(pin23) → ②(pin25) 를 0.6초 안에 연속 태그하면 이전 단계의 `display:'none'`(600ms) 이
방금 뜬 mission2 를 지워 **다음 핀까지 공백**이 됐다(재현 확인). 대기가 긴 단계(20~30초) 안에서 다음 카드를 찍으면
반대로 **옛 미션이 뒤늦게 튀어나와** 최신 미션을 덮었고, 게임 도중 재시작하면 스냅샷 재생으로 이게 한꺼번에 터졌다.

**조치(v140)** — `app.js` 의 표시 계층을 스케줄러로 교체했다. 자세한 규칙은 `PROTOCOL.md`.
- 지우기는 타이머 없이 `hide` 클래스만 (뒤늦게 화면을 지우는 타이머 자체를 없앰)
- 칸(mission/details/location/inprogress)마다 **세대(generation)** — 최신 단계가 항상 이긴다
- 표시할 때 `hide` 를 반드시 제거 (`.hide` 가 `.show` 뒤에 선언돼 둘 다 붙으면 투명해짐)
- SNS 개방 같은 **게임 진행 처리는 `sideEffect`** 로 분리 — 화면 표시가 취소돼도 실행된다
- 스냅샷 재생은 연출 없이 **진행 순서(`rank`)로 최종 상태만** 즉시 그린다

검증: `test/phone-display/` (겹침 14 PASS + 정상 플레이 20단계 20 PASS, 참조 이미지 집합 v139와 동일)

## 2026-08-03 추가: 태블릿 시간 자동 동기화 (v141)

폰이 게임 도중 재시작되면 진행은 스냅샷으로 따라잡지만 **타이머는 복구할 길이 없어 1:40:00 부터 다시 셌다.**
GM 이 [시간 적용]으로 손수 맞추기 전까지 손님은 틀린 시간을 봤다.

**조치(v141)** — 살아 있는 다른 태블릿에서 받아온다. 서버 수정 불필요(simPin 채널 재사용, `__timereq__` / `__timeres__`).
- 재시작한 폰이 접속 즉시 물어보고, 못 받으면 **10초마다** 다시 묻는다(다른 태블릿을 나중에 켜도 맞춰짐)
- **신뢰(synced)** 개념이 핵심 — 응답도 채택도 "믿을 만한" 폰만 한다.
  스냅샷 재생으로 시작된 타이머(= 재시작 복구본)는 **못 믿는 값**으로 표시(`tU-`)해 절대 퍼뜨리지 않는다.
  없으면 재시작한 폰끼리 틀린 1:40:00 을 주고받아 둘 다 확신하는 오답이 된다.
- 이미 아는 폰은 남의 보고에 흔들리지 않는다(양쪽 다 벽시계 기준이라 드리프트 없음)
- 자동 동기화는 ack 를 보내지 않는다 — 뷰어에 GM 이 누르지도 않은 "✔ 폰 적용" 이 뜨면 안 되므로
- **뷰어**: 못 믿는 폰(`tU-`)의 보고로 시계를 바꾸지 않고 "미동기화"로 표시, 두 폰이 5초 넘게 어긋나면 "폰 시간 불일치" 경고

검증: `test/reset.test.mjs` I1~I25 (신뢰 판정 / 응답·채택 규칙 / 릴레이 경유 2대 연동 / 뷰어 표시 / 하위호환)
+ `test/phone-display/live-timesync.test.mjs` — **라이브 파일로** 폰 2대를 띄워 실제 복구까지 확인(매장 릴레이에는 접속 안 함)

## 공유 상태 — 힌트폰 2대 + 뷰어 (v139)

힌트폰 **2대가 동시에** 돌아간다. 2대와 뷰어가 하나의 상태를 공유한다.

**초기화** — 아무 폰이나 좌측 하단 **10탭** → 그 자리에서 **다른 폰 + 뷰어가 즉시 초기화**되고,
이 폰은 새로고침돼 **연결모드 버튼 화면에서 대기**한다. 팀 교대 때 폰 하나만 만지면 된다.
(연결모드 버튼을 눌러 재접속할 때 중복 초기화는 일어나지 않는다)

초기화되는 것: 메인 진행·업적 퀘스트·상태 플래그 / 타이머(1:40:00 정지, 예약된 137초 시작 취소)
/ 폰 시간동기 표시 / 개인 SNS·DM / 수신 카운터. 뷰어 상단에 초기화 알림 토스트가 뜬다.

**SNS/DM** — 한 폰에서 터치(15탭/10탭)로 켜면 다른 폰에도 자동 활성화. 뷰어 버튼은 2대 전부에 적용.
뷰어는 "**● 활성 1/2대**"처럼 **폰 대수로 집계**해 보여준다.

**힌트 사용 개수** — 힌트 모달 ENTER 버튼 아래에 "USED n회". 같은 힌트를 다시 봐도 안 오르고(고유 힌트만),
폰 2대가 개수를 공유한다. 뷰어에는 개수 + 어떤 코드를 몇 시에 봤는지까지 남고 3회 노랑·5회 빨강.

- 초기화 통보는 **페이지 로드당 1회**만 → 게임 중 ws가 끊겼다 재연결돼도 안 지워진다.
- 통보를 **받은** 폰도 새로고침으로 초기화된다 → 양쪽 다 연결모드 버튼 화면에서 대기.
  (표식을 남겨 되받아치지 않으므로 폰끼리 무한 초기화는 없다)
- **DM이 "1/2대"로 보이는 건 정상.** DM 활성은 그 폰에서 DM 탭을 열면 꺼지는 알림 플래그라
  꺼짐은 전파하지 않는다(한쪽이 읽었다고 다른 폰 알림을 지우면 안 되므로).
- **새로고침의 "이유"를 구분한다**(v138): 10탭·원격 초기화로 인한 새로고침은 슬레이브 스냅샷을 무시해
  깨끗한 대기 상태가 되고, 그 밖의 새로고침(배터리·앱 종료·오탭)은 스냅샷으로 **진행을 따라잡는다**.
- ⚠ 그래도 폰이 사고로 재시작되면 부팅 통보가 나가 **양쪽 폰과 뷰어가 초기화된다**(선택한 모델의 이면).
- 필요 조건: **두 태블릿 모두** `websocket.js` **v141** + 서버 simPin 패치.
- 뷰어 헤더의 **[진행 초기화]** 버튼은 뷰어 화면만 초기화한다(폰에는 안 나감).

## 안전 원칙
- 뷰어는 **master 다중접속(읽기)** — 실폰 연결에 영향 없음.
- 조작은 "무장(ARM)" 토글 + 확인창을 거쳐야 전송. `simPin`은 폰만 진행시키고 **물리 아두이노는 안 건드림**.
- 타이머: 평소엔 폰이 10초마다 보고하는 실측을 따라간다. **"시간 적용"으로 폰 시간을 직접 바꿀 수 있다**(v139,
  simPin `__settime__`). 적용되면 "✔ 폰 2대 적용", 3초 내 회신이 없으면 "✖ 폰 적용 실패"가 뜬다.
- **재시작한 태블릿은 다른 태블릿에서 남은시간을 자동으로 받아온다**(v141). 뷰어는 아직 못 받은 폰(`tU-`)의
  보고로는 시계를 바꾸지 않고 "미동기화"로 표시하며, 두 폰이 5초 넘게 어긋나면 "폰 시간 불일치"를 띄운다.
