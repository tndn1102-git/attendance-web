## 2. 앱(https://desirenvy1.duckdns.org/knara/) 구조 — 브라우저에서 실측
- 단일 HTML + 인라인 번들 JS 약 2.05MB (three.js 3D). **네트워크 호출이 전혀 없다**: fetch 0 · XHR 0 · sendBeacon 0 · WebSocket 0. 상태는 localStorage 한 키(JSON)에 저장(blank()/save()).
  → 통계 수집은 앱에 **수집 스니펫을 추가**해야 가능. 앱 소스는 이 PC에 없음(발주처/다른 PC). 따라서 산출물에 "앱에 넣을 track 스니펫 + 호출 지점 명세"를 반드시 포함.
- 접근: 사이트는 "발급된 링크로만" 열리는 미리보기(403). 사용자 크롬에는 쿠키가 있어 열림.
- 언어 5개: ko, en, ja, zh, es. 발주처 요구로 **TTS 금지**, 음성 입력은 박수만.
- 스태프 모드: 주소에 staff 표시 시 '놀이 점검' 노출, staffPin '2026', deskBeacon 'KNARA'(운영 데스크 개념). 운영 패널 존재.

## 3. 관람 흐름 (보고서 7~8장)
첫 화면 → 센서 권한 → 노리개 고르기(직업) → 메인 지도 → 도시 누르면 그 도의 방 → 판1(공용, 안 깬 놀이 먼저) · 판2(직업 놀이, 자리는 섞임) · 판3(공용, 앞 판과 다른 손놀림) → 도 색 획득 → … 8색 → 결과 카드(나의 노리개).
판 하나: 시작 오버레이(동사·조작 그림·한 줄 지시, 톡 하면 시작) → 플레이(목표 n회 · 제한 ~14초, 기회/실수 점 표시) → 성공(시계 멈춤·마무리 연출) / 실패(다른 놀이로 교체, 직업 놀이는 직업 놀이로).

## 4. 통계로 꼭 답해야 하는 질문 (제안서 약속 + 보고서 "남은 일"에서 파생)
1. 놀이별 성공률·실패율·평균 소요(초) — 난이도 조정의 근거. 제한시간 대비 실제 클리어 시간 분포.

3. 센서 권한 거부율·대체 조작(끌기·톡) 사용률 — "터치 외 조작이 실제로 될 것" 요구 검증.
