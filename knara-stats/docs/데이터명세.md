# 데이터 명세 — 이벤트 · 필드 · 테이블 · 보존기간 · 집계 정의

## 0. 수집 흐름
전시장 QR → **입장 페이지**(`entry/index.html`: 언어·안내·나이대·성별·동의 → `enter`·`lang`·`demo`·`consent`) → **게임**(`role`·`room_*`·`play_*`·`all_done`·`result`·센서·오류). 세션 id 는 입장 페이지에서 생성되어 게임으로 이어진다(같은 origin 이면 sessionStorage, 다르면 `?sid=&s0=`). 미동의 세션은 `consent=declined` 1건만 남고 클라이언트가 수집을 끈다(localStorage `kstat:optout`).

## 1. 전송 단위 (track.js → `POST /api/track`)

본문은 JSON(Content-Type `text/plain` — sendBeacon 호환). 배치 1건 = 세션 1개의 이벤트 묶음.

```json
{
  "v": "1.0",                 // 스니펫 버전
  "sid": "3f9a…(32 hex)",      // 세션 id — 폰 브라우저가 무작위 생성(crypto.getRandomValues). 탭(sessionStorage) 단위
  "s0": 1762045200000,         // 세션 시작 시각(클라이언트 ms)
  "now": 1762045260000,        // 전송 시각(클라이언트 ms) → 서버가 시계 오차(skew) 보정에 사용
  "staff": false,              // 스태프 점검 모드 여부
  "tk": "…",                   // (선택) TRACK_TOKEN
  "meta": { "sw":390,"sh":844,"vw":390,"vh":664,"dpr":3,"lang":"ko-KR","cores":6,"mem":4,"ref":"direct","app_ver":"1.0.0" },  // enter 가 든 배치에만
  "events": [ { "q":1, "t":1762045200100, "e":"enter" }, { "q":2, "t":…, "e":"play_start", "room":"land", "slot":1, "game":"tea", "kind":"chef", "role":"chef", "target":4, "limit_s":14 } ],
  "logs":   [ { "q":9, "t":…, "level":"error", "message":"…", "source":"…", "lineno":1, "colno":2, "stack":"…", "page":"/knara/", "room":"land", "game":"tea" } ]
}
```

제한: 배치당 events ≤ 100, logs ≤ 25, 본문 ≤ 256KB. 세션당 로그 ≤ 25(클라이언트), 큐 ≤ 600건(클라이언트).

### 시각 처리
- `skew = 서버수신시각 − now`. 모든 `t` 에 skew 를 더해 `event_at` 으로 저장 → 폰 시계가 틀려도, 오프라인 큐로 늦게 와도 실제 발생 시각이 보존된다.
- `day_kst`·`hour_kst` 는 **세션 시작(s0)** 의 KST 날짜·시 → 한 세션은 하루에 귀속(자정 넘김 분리 없음). 기간 필터는 이 값으로 건다.
- 범위 밖(미래 5분 초과·과거 45일 초과)은 서버 시각으로 대체.

## 2. 이벤트 사전

| e | 언제 | 필드 | 집계에서의 뜻 |
|---|---|---|---|
| `enter` | 입장 페이지(또는 게임 직접 진입) 로드, 세션당 1회 | value=`staff`(스태프일 때) | 총 방문자·오늘 방문자 |
| `consent` | 입장 페이지 "시작하기"/"동의 없이 시작" | kind=동의 문구 버전(`v1`), value=`agreed`|`declined` | 동의율. `declined` 이후엔 어떤 이벤트도 오지 않음(클라이언트 opt-out) |
| `demo` | 입장 페이지 나이대·성별(선택 사항) | kind=`10s`|`20s`|`30s`|`40s`|`50s`|`60s+`|`skip`, value=`f`|`m`|`other`|`skip` | 나이대·성별 분포(구간값만, 그 외 값은 `skip` 으로 저장) |
| `sensor` | 권한 응답 | kind=`motion`\|`mic`\|`camera`, value=`granted`\|`denied`\|`unsupported` | 권한 허용/거부율 |
| `lang` | 입장 페이지 언어 선택(게임 안에서 바꾸면 다시) | lang | 언어 비율 |
| `role` | 노리개 확정 | role=`idol`\|`chef`\|`creator` | 직업 비율 |
| `map` | 메인 지도 표시 | — | 퍼널 |
| `room_enter` | 방 입장 | room | 도별 진입 |
| `play_start` | 판 시작 | room, slot(1~3), game, kind, role, target, limit_s | 시도 |
| `play_clear` | 판 성공 | + dur_ms, hits | 성공·소요 |
| `play_fail` | 판 실패 | + dur_ms, hits, value=`timeout`\|`miss` | 실패·실패 사유·실패 시 진척도(hits/target) |
| `play_swap` | 실패 후 교체 | game(실패한 놀이), value(새 놀이) | 교체 |
| `room_done` | 도 색 획득 | room, dur_ms(방 진입→완료), hits(완료한 도 수) | 도 완료·소요 |
| `all_done` | 8색 완주 | dur_ms(입장→완주), role | 완주·완주 소요 |
| `result` | 결과 카드 | dur_ms, role | 결과 도달 |
| `quality_down` | 화질 하향 | kind(단계), value(fps), room, game | 저사양 대응 발생 |
| `webgl_lost` | 컨텍스트 손실 | room, game | 3D 멈춤 |
| `fallback_input` | 대체 조작 사용 | kind=`drag`\|`tap`, room, game | 센서 대체 비율 |
| `x_*` | 앱 자유 이벤트 | 임의 | 저장만(대시보드 미표시) |

필드 범위(서버 검증): 문자열 id 는 `[A-Za-z0-9_:.-]{1,40}`, value ≤ 60자, dur_ms 0~6시간, hits/target 0~9999, limit_s 0~3600, slot 1~9. 범위 밖은 NULL.

## 3. 테이블 (Postgres 정본, SQLite 는 타입만 다름)

### `knara_sessions` — 세션 1행
| 컬럼 | 타입 | 뜻 |
|---|---|---|
| sid | TEXT PK | 무작위 세션 id |
| started_at / received_at | TIMESTAMPTZ | 세션 시작(보정) / 서버 수신 |
| day_kst | TEXT `YYYY-MM-DD` | 세션 시작일(KST) — 기간 필터 키 |
| hour_kst | INT | 세션 시작 시(KST) |
| is_staff, is_mobile | BOOL | |
| os, os_ver, browser, browser_ver, device, inapp | TEXT | UA 파싱 결과(인앱 = 카카오톡·네이버앱 등) |
| screen_w/h, viewport_w/h, dpr | INT/REAL | 화면 메타 |
| cores, mem_gb | INT/REAL | 성능 힌트(브라우저가 주는 범위값) |
| lang, ref, app_ver, snippet_ver | TEXT | 브라우저 언어, 유입(direct/link), 앱·스니펫 버전 |
| ua | TEXT(≤300) | UA 원문 |

### `knara_events` — 이벤트 1행 (append-only)
id, sid, seq, event, event_at, received_at, day_kst, hour_kst, is_staff, room, slot, game, kind, role, lang, value, dur_ms, hits, target, limit_s.
`UNIQUE(sid, seq)` → 재전송 중복은 `ON CONFLICT DO NOTHING`.
인덱스: (day_kst, event), (sid), (game, event).

### `knara_logs` — 오류 1행
id, sid, seq, level, message(≤1000), source, lineno, colno, stack(≤4000), page, room, game, event_at, received_at, day_kst, is_staff, is_mobile, os, os_ver, browser, browser_ver, device, inapp. `UNIQUE(sid, seq)`.
`Script error.`(크로스오리진 잡음)는 저장하지 않음.

## 4. 집계 정의 (`GET /api/stats?from&to&staff`)

기간 = `day_kst BETWEEN from AND to`(세션 시작일 기준, 둘 다 포함). `staff=0`(기본) 이면 `is_staff` 세션 제외.

| 지표 | 정의 |
|---|---|
| 총 방문자(세션) | 기간 내 이벤트가 1건 이상 있는 sid 수 |
| 오늘 방문자 | 선택 기간과 무관하게 `day_kst` = 오늘(KST) 인 sid 수 |
| 동의율 | `consent=agreed` 세션 / (`agreed` + `declined`) |
| 나이대·성별 | sid 별 `demo` 의 kind/value(마지막 값) 분포. 건너뜀 = `skip` |
| 퍼널 단계 | 그 이벤트가 1회 이상 있는 sid 수. "방문 대비 %" = 단계/방문, "직전 %" = 단계/직전 단계 |
| 8색 완주 / 완주율 | `all_done` 있는 sid / 방문 |
| 완주 소요 | `all_done.dur_ms` 의 중앙값·25%·75% (10초 버킷 히스토그램에서 계산, 오차 ±5초) |
| 완료 도 개수 분포 | sid 별 `COUNT(DISTINCT room WHERE room_done)` 의 분포 0~8 |
| 놀이 시도/성공/실패 | `play_start`/`play_clear`/`play_fail` 건수 |
| 판정수 | 성공+실패(결과가 난 판) |
| 성공률 | 성공 / 판정수 |
| 성공 소요(중앙) | `play_clear.dur_ms` 중앙값(0.5초 버킷, 오차 ±0.25초) |
| 소요/제한 | 성공 소요 중앙값 / 제한시간(이벤트의 `limit_s`, 없으면 카탈로그값) |
| 시간초과 실패 | `play_fail.value='timeout'` |
| 실패 시 진척도 | Σhits/Σtarget (실패 판) |
| 교체 | 그 놀이에서 실패 뒤 `play_swap` 한 수 |
| 완주 기여 | 8색 완주(`all_done`) 세션 중 그 놀이를 `play_clear` 한 sid 수 |
| 판정 | 판정수 ≥ 20 일 때: 성공률 < 45% → **어려움 의심**; 성공률 ≥ 92% 이고 중앙 소요 ≤ 제한의 50% → **쉬움 의심**; 그 외 **적정**. 판정수 < 20 → **표본 부족**. (상수는 `lib/stats.js` 상단 `MIN_SAMPLE/HARD_RATE/EASY_RATE`) |
| 도별 진입/완료/완료율 | `room_enter`/`room_done` 있는 sid 수(방별) |
| 도별 소요 | `room_done.dur_ms` 중앙값(5초 버킷) |
| 센서 허용/거부/미지원 | `sensor` 를 kind×value 로 sid 수. 거부율 = 거부/(허용+거부+미지원) |
| 센서 거부 세션 | `sensor.value='denied'` 가 하나라도 있는 sid |
| 대체 조작 세션/횟수 | `fallback_input` 의 sid 수 / 건수 |
| 화질 하향 세션(율) | `quality_down` 있는 sid (/방문). 기기별은 sessions 조인 |
| WebGL 손실 세션 | `webgl_lost` 있는 sid |
| 기기 분포 | `knara_sessions` 기간 내 행을 os/os_ver/browser/device/inapp/뷰포트@dpr 로 묶음(세션 1대 = 1) |
| 인앱 비율 / iOS 인앱 | inapp 이 NULL 아닌 세션 / 그중 iOS |
| 오류 건수·세션 | `knara_logs` 건수 / DISTINCT sid. 묶음 = 메시지 앞 120자 × 브라우저 × OS |
| 직전 기간 비교 `prev` | 같은 길이의 바로 앞 기간(`from−days ~ from−1`)을 같은 정의로 계산: `visits`·`finished`·`finish_rate`·`plays`·`clear_rate`. 개요의 "▲ 10% 지난 7일 274명 대비", "▲ 2%p" 델타가 여기서 나온다. 앞 기간에 자료가 없으면 0 → 화면은 "비교 기간 자료 없음" |

모든 SQL 은 Postgres·SQLite 공통 부분집합(CASE/SUM/COUNT DISTINCT/서브쿼리)만 사용하므로 두 저장소에서 같은 숫자가 나온다. 분위수는 SQL 히스토그램 + Node 계산.

## 4-1. 화면에 보이는 것 / 숨긴 것
개요 탭은 총 방문자·완주율(완주자 수)·오늘 방문자 + 나이대(응답자 기준, `skip` 제외)·성별·언어(상위 3 + 기타)·접속 기기(iOS/Android/기타) 퍼센트(정수) + 일별 차트만 보여 준다. 건수·동의율·시간대·노리개·브라우저/인앱·OS 버전·기기 모델·센서·화질 하향·퍼널·완료 도 개수·도별·오류는 **자세히** 탭과 CSV 에 있다. 집계 정의는 위 표와 같고 표시만 줄였다.

## 5. 내보내기 (`GET /api/export?kind&from&to&staff`)
`demo`(동의·나이대·성별·언어·노리개·OS·브라우저) · `games`(놀이별, 완주 기여 포함) · `rooms`(도별) · `funnel` · `daily` · `sessions`(세션 1행+기기, 최대 전체) · `events`(원자료, 최대 20만 행) · `logs`(최대 2만 행). UTF-8 BOM + CRLF, 엑셀에서 바로 열림.

## 6. 보존기간
| 데이터 | 보존 | 삭제 방법 |
|---|---|---|
| 세션·이벤트 원자료 | 400일 | `node scripts/purge.js` (월 1회 권장) |
| 오류 로그 | 180일 | 〃 |
| 집계 CSV | 발주처가 내려받아 보관 | — |

Neon Free 용량(0.5GB) 기준: 이벤트 1행 ≈ 200B → 하루 500세션 × 90이벤트 = 45,000행 ≈ 9MB/일 → 전시 2개월 ≈ 540MB 는 상한에 가깝다. **운영 중 월 1회 `purge` 또는 이벤트 보존을 120일로 낮추는 것을 권장**(세션 수가 적으면 무관). 세션 테이블은 1행 ≈ 500B 로 부담 없음.

## 7. 수집하지 않는 것
이름·연락처·계정·정확한 나이·사진·음성·카메라 영상·쿠키·광고 id·IP 주소·정확한 위치·입력한 텍스트. 나이대·성별은 구간값만 받고 식별 정보와 결합하지 않는다. 요청 헤더에서 읽는 것은 `User-Agent` 하나이며 IP 는 코드 어디에서도 참조하지 않는다(`lib/ingest.js`).
